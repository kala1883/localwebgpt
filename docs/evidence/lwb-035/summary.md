## 0. 这一轮的证据是在什么装置上采的

三条执行步骤与三条验收标准的原文：

> 1. 提供目录/单文件授权、只读模式、写入模式与风险说明。
> 2. 显示 daemon、MCP adapter、tunnel-client 与账号验收状态，不把进程运行等同于平台可调用。
> 3. 提供脱敏诊断、一键暂停、重新验证和本地启动帮助。
>
> (a) 非技术用户能知道当前哪台机器、哪些目录正在暴露。
> (b) 无法越过 G0/G4 开关直接授权直写。
> (c) 停机/睡眠/断网状态不显示成正常在线。

| 段 | 装置 | 为什么非这样不可 |
| --- | --- | --- |
| §0 ~ §3 | **生产装配根**（`startDaemon`，与 `npm run daemon` 同一个函数、同一套受保护存储布局，只有根被 `--home` 覆盖） | 前面几份任务的界面证据是「按契约形状合成的探针数据」。这一份换成真服务端，才谈得上「界面显示的结论」与「服务端的真实状态」是不是同一件事 |
| §2 | 控制台**自己的**兑换链路（`bootstrapConsoleSession`：读片段 → 抹地址栏 → 兑换）与**自己的**客户端（`ControlClient`：摘要 + 一次性 nonce + CSRF + Origin） | 这两段是 LWB-012 的交付物，也是控制台唯一会用的那一条路。用 `curl` 复刻一遍只能证明「接口长得像」，证明不了控制台能走通 |
| §3.10 | 真控制面上的真登记（一次性 nonce 绑定 `(route, subject, bodyDigest)`） | nonce 绑定是这条链路上最容易「看起来对了其实是错的」的一处（见 `client.ts` 里 `authorizeMutation` 的说明）。只有真服务端会拒绝一张算错的 nonce |
| §4 | 同一层判定 + **合成**的全绿读数 | 反例必须能通过：一条只会说「不」的判定会让验收标准 3 的每一条断言都变绿，而它是错的 |
| §5 | 真读数 + 一个**藏在别名里的**绝对路径 | 别名是操作者自己起的，因此它是「脱敏要接的第 2 层」的天然入口；合成的假数据造不出这个位置 |
| §6 | 一个**真 socket 上的、会谎报的**服务器 | 「这一层不是安全边界」必须量出来，而不是写在注释里 |

## 1. 界面文件还没有人托管：三行实测

`help.ts` 的 `console_page_missing` 那一条里写着「本机实测（2026-09-26）：`/` 与
`/index.html` 都是 404，而 `/api/status` 答 401」。§1 当场把这三行重新量了一遍：

```
PASS 1.1 GET / 答 404（服务在跑，但没有人托管界面文件） — HTTP 404
PASS 1.2 GET /index.html 也答 404 — HTTP 404
PASS 1.3 GET /api/status 在无会话时答 401 —— 这正是它该做的 — HTTP 401
NOTE 1.4 这三行与帮助文本的关系 — `help.ts` 的 console_page_missing 那一条里写着同样三行；LWB-039 托管界面之后 1.1/1.2 会失败，那时该改的是帮助文本（这条断言是有意留下会过期的）
```

`1.1` / `1.2` 是一条**有寿命的**断言：LWB-039 的启动器托管界面文件之后，`/` 就不再是 404，
于是这两条会失败。那正是它们存在的理由 —— 帮助文本里那句事实与它有一条会自动过期的接缝，
而不是静静地变成一句谎话。`NOTE 1.4` 把这件事写在证据里，免得将来有人把它当成回归。

`1.3` 是**三行里唯一一条正向断言**：没有会话时 `/api/status` 必须答 401。
「服务在跑」与「服务愿意跟你说话」是两件事，而控制台的第一屏正是靠这一条分辨它们。

## 2. 用**打印出来的**地址走完整条兑换链路

```
PASS 2.1 控制台自己的兑换链路能从真地址换到真会话 — session_id=s1-9ee0a1f921af（服务端签发）
PASS 2.2 地址栏片段在兑换**之前**被抹掉 — strip → fetch
PASS 2.3 会话凭证到了 cookie 罐里，且带着正确的名字（后续调用靠它鉴权） — Cookie: __Host-lwb_console=‹已隐去›
PASS 2.4 同一张启动令牌**再兑一次**被拒（一次性） — HTTP 403
PASS 2.5 被拒的响应里不出现令牌本身 — 判据是「找不到」，而不是「换了一句话」
```

四件事各自成立才有意义：

- `2.2` 判的是**次序**（`strip → fetch`），不是「抹过了」。片段里的令牌在兑换**之前**
  就必须从地址栏消失：先兑换再抹，窗口期内它已经进了浏览器历史与可能的前端日志。
- `2.4` 与 `2.1` 必须成对读：第一次兑换成功、第二次**同一张**被拒。
  只证第一次的实现（一张永久有效的启动令牌）会让「用后即焚」这句话失去意义。
- `2.5` 的判据是**找不到**那一串，不是「换了一句话」。把错误信息写得温和一点
  并不等于没泄漏 —— 这是同一个错误在两种措辞下的区别。

### 2.1 装置自述：这一节里写错过两次，两次都留在代码注释里

第一次：`readSessionCookie` 返回的是 cookie 的**值**（它内部已经按名字找过了），
把返回值直接塞进 `Cookie` 请求头，发出去的就是一个**没有名字**的值 ——
服务端按名字找，找不到，于是 401。症状与「会话过期」一模一样，而原因是装置少拼了一个名字。

第二次比第一次严重得多：同一个返回值曾经被**打印进证据**（`2.3` 那一行写的是
`cookie().split('=')[0]`，看着像在只回显名字，实际上把一张会话密钥原样写了出去 ——
值里没有 `=`，`split` 出来的就是全部）。这一条是**外发**的：证据会连同它的输出一起提交。

两处都已经修掉，而第二处留下了一道**结构性**的防线（§8.2）：末段的自查拿
`@lwb/contracts` 声明的凭证形状（`CONTROL_TOKEN_PATTERN_SOURCE` —— 与
`packages/egress` 筛查模型可见内容用的是**同一条规则**）对每一行打印出去的字复查一遍。
自查规则与真正的出站规则分成两份，就会出现「自查说干净、出口漏了」这种最不该出现的组合；
这一次它抓到的是真泄漏。

## 3. 真读数 → 控制台判定（验收 1 / 2 / 3 的数据源都是真的）

```
PASS 3.1 控制台解析器认得真服务端的 /api/status — HTTP 200
PASS 3.2 机器身份解析出来了（这是「哪台机器」那一行的来源） — 当前机器：mj-LAPTOP-FVES06T1 · win32 · x64
PASS 3.3 门禁四格与能力开关五格都解析出来了（缺一格会整份作废）
PASS 3.4 版本与服务端自报的接口清单也在 — 21 条路由
PASS 3.5 真读数下：四条腿齐全，本机服务那一格是「在运行」 — 在运行
PASS 3.6 真读数下：平台**不可调用**（G0 未通过 + 隧道无读数） — 读不到连接登记表，无法证明本机有一条可用的模型侧连接。
PASS 3.7 真门禁下直写是关着的，理由来自门禁本身 — 4 项原因：G0（真实网页接入验证）未通过。
PASS 3.8 真服务端的路由清单里没有任何「改门禁 / 改能力开关」的入口 — 21 条路由一条都不匹配
```

`3.6` 与 `3.7` 是这一节的核心：**本机服务在运行，而平台不可调用**。
这正是执行步骤 2 那句「不把进程运行等同于平台可调用」在真数据上的样子 ——
两句话同时在屏幕上，而不是让「在运行」这一个词独自承担两种意思。

`3.7` 的理由列表有 4 项、第一项是 G0：界面说的是**门禁自己**给的理由
（`limitationsOf` 从门禁常量推导），不是一句手写的文案。手写的那一份会与真实开关脱节，
而脱节的方向通常是「限制清单里还写着能读、开关其实已经关了」。

`3.8` 是一条**结构性**断言，问的是真服务端自报的那 21 条路由里有没有
「改门禁 / 改能力开关」的入口 —— 一条都没有。它把 `NOTE 3.9` 那句话
（门禁来自 `apps/daemon/src/gates.ts` 的常量，不是运行期可写的状态）从注释变成了判据。
配合 §6，「界面能不能信」这个问题的答案就有了着落：不能信界面，但**可以**看服务端的门禁常量。

### 3.1 真控制面上的真登记

```
PASS 3.10 真控制面上登记成功（一次性 nonce 绑定 + CSRF 头 + Origin 全部通过） — workspace_id=ws_207700ab403e0ec2cae56ac1bfdd3791
PASS 3.11 服务端回报的根与登记时给出的**逐字符相同** — 路径不做规范化
PASS 3.12 workspaces.list 的真响应能被控制台解析成一行 — 1 行
PASS 3.13 解析出来的绝对路径与登记的一致（这一行是给本地操作者看的）
PASS 3.14 真数据上的暴露摘要：登记 1 个、但没有任何内容会被交出去 — 已登记 1 个根，但**当前没有任何内容会被交给模型** —— 读取能力由门禁关闭。
PASS 3.15 service.pause_status 的真响应能被解析 — paused=false stopping=0
PASS 3.16 真读数下可以暂停；恢复不提供（要求一份新鲜且明确说停着的读数） — NOT_PAUSED
PASS 3.17 connections.list 的真响应能被解析，且行数与线上响应一致 — 线上 1 行 / 解析出 1 行
```

- `3.11` 的「逐字符相同」是刻意的：控制台显示的是**操作者自己给出的那个写法**。
  在这里做规范化（折叠 `..`、统一分隔符、去尾斜杠）会让界面显示一个
  与操作者输入不同的路径，而路径正是他要去核对的**那一件**东西
  （对象身份的判定在服务端，见 I05/I03 与 LWB-028）。
- `3.14` 是验收标准 1 的后半句。它要求两件事一起：**登记了 1 个**（界面没有把
  「登记过」当成「没有」）而**没有任何内容会被交出去**（读取能力由门禁关闭）。
  只证后者的实现（一个恒为 0 的计数器）与一个正确的计数器在「只看 0」的断言下长得一样。
- `3.16` 判的是**不对称**：暂停可以按，恢复不提供。恢复的判据是一份
  **新鲜且明确说停着**的读数 —— 一个「没取到读数就允许恢复」的界面，
  会在最需要它的那一刻（读数取不到，通常因为服务正忙/刚起来）给出一个越权的按钮。
- `3.17` 比的是**行数**：真响应里有几行，解析出来就该有几行。
  「0 行」与「解析失败」在界面上长得一样，而它们要采取的行动完全不同。

### 3.2 这一节抓到的一处**真实缺陷**（见偏离项 140）

第一次采集时 `3.2` 是**红的**：

```
FAIL 3.2 机器身份解析出来了（这是「哪台机器」那一行的来源） — 当前机器：未知（本机服务没有给出机器读数）
```

验收标准 (a) 的原文是「非技术用户能知道当前**哪台机器**」，而
`GET /api/status` 的响应里**没有**机器身份 —— 控制台那一格因此永远是「未知」，
而它与「这次读取失败了」长得一模一样：操作者会去重启一个没坏的东西。

界面那一侧无法自救：浏览器知道的是**浏览器所在**的机器，与「本机服务跑在哪台机器上」
是两个问题（控制台将来可能被从另一台机器上打开）。于是这一条修在服务端：
`apps/daemon/src/runtime/assembly.ts` 的状态投影多一格
`machine: { hostname, os, arch }`，并配一条回归测试
（`tests/windows/daemon-assembly.test.ts` 第 4 例：真兑换 → 真会话 → 真 HTTP GET，
并断言这一格**没有**进工具面的状态源 —— 机器身份只走控制平面那一侧）。

## 4. 反例：同一层判定，喂假读数（验收标准 3 的判决点）

```
PASS 4.1 对照：四条腿与门禁全绿时**会**算出可调用（这一层不是恒定说「不」）
PASS 4.2 同一份全绿读数，一小时后再看：不可调用，且本机服务那一格是「读数已过期」 — 读数已过期
PASS 4.3 而且它**不说**「等于在线」（停机与睡眠不得显示成正常在线）
PASS 4.4 断网由网络本身否决，且那条理由排在最前 — 这台机器的网络已断开。隧道与账号验收都要过网络，因此平台侧此刻一定不可调用。
PASS 4.5 「没发现坏消息」不等于可调用：缺隧道读数时仍然不可调用
PASS 4.6 门禁读数缺一格就整份作废：直写关闭，理由是「读数不完整」而不是「某项未通过」 — 门禁读数缺失，按未通过处理。
PASS 4.7 没有会话时暂停与恢复都不给，并把下一步说清楚 — 还没有控制台会话，暂停与恢复都按不动。本地启动命令会打印一个带一次性令牌的地址，用它打开控制台。
PASS 4.8 没有读数时那一格是「没有读数」，不是「没暂停」
```

`4.1` 是**非平凡性前提**：没有它，上面每一条「不可调用」都可能来自一个恒为「不可调用」的实现。
`4.2` 是验收标准 3 的正面判据：**同一份**全绿读数在一小时之后既不可调用、
本机服务那一格也变成「读数已过期」—— 判定是**时间函数**，不是「值函数」。
一个只比较 `value` 的界面会把一小时前的「一切正常」原样显示成一小时后的「一切正常」。

`4.3` 是措辞判据：那句通栏**不得**包含「正常在线」。停机与睡眠的共同点是
「本机服务此刻什么都不知道」，而界面能说的最多是「读数已过期」。

`4.4` 判的是**次序**：断网那条理由排在**最前**。理由的排序不是排版 ——
操作者按顺序读，第一条就是他该去处理的那一件；而断网是唯一一条
「处理完它，别的问题可能一起消失」的理由。

`4.5` 是一条容易写反的判据：**缺一份读数**（没发现坏消息）也**不等于**可调用。
这一格要的是「有一条正面的隧道读数」——「无法证明」与「证明为假」在这里是同一种处置，
但两句话不该混成一句。

`4.6` 与 `4.8` 是同一条纪律的两处：门禁读数缺一格 ⇒ 整份作废（理由写「读数缺失」，
不是「某项未通过」）；暂停没有读数 ⇒ 那一格是 `null` 而不是 `false`。
把「没有读数」显示成「没暂停」正是 `readings.ts` 文件头要防的那件事，
而它最容易在模板里被重新引入（`v-if="paused"` 与 `v-if="!paused"` 的两支都会落到「没暂停」那一支）——
所以 `.vue` 层拿到的 `paused` 是一个**三态** `boolean | null`，
`tests/setup-view.spec.ts` 的 C4 断言渲染出来的是 `data-paused="unknown"` 而不是 `"false"`。

## 5. 脱敏诊断跑在**真数据**上

```
PASS 5.1 真根路径在可复制的文本里一次都不出现
PASS 5.2 台账点名了被隐去的字段（别名里藏下的那一个被抓住了） — workspaces[0].alias
PASS 5.3 终检通过，因此界面会给「复制」按钮 — 未命中任何模式
PASS 5.4 终检的对象是**将被复制出去的那串字节**（台账写在终检之前） — 台账不在扫描之外
PASS 5.5 诊断里不含任何凭据形状的东西
```

`5.2` 用的是一个**真登记出来的**工作区，只把它的 `alias` 换成那个绝对路径 ——
别名是操作者自己起的，因此它是「第 2 层擦洗」的天然入口。合成数据造不出这个位置：
要造它，得先知道「别名可以藏下一个路径」这件事。

`5.4` 是这一节里唯一一条关于**次序**的断言：台账（「已隐去：…」那几行）写在终检**之前**。
反过来的实现在平时看不出问题，只在台账本身含有一个不该出现的形状时才暴露 ——
而那时它已经是一段会被复制走的文本了。

## 6. 一个**会说谎的服务器**：界面的判定不是安全边界

```
PASS 6.1 谎报的门禁**能**让界面说出「直写：已打开」 — 直写：已打开（四项门禁与服务端开关一致）。
NOTE 6.2 这正是要写下来的事实 — 界面这一层**不是**安全边界：一个谎报的服务端能让它把坏消息显示成好消息。真正的边界在服务端（能力表 + gates 常量 + 3.8 那条结构性断言）
PASS 6.3 但它仍然打不开「平台可调用」—— 那需要一条**正面**的隧道读数 — 隧道状态没有本机读数：无法证明本机工具面已经被注册到平台上。
PASS 6.4 谎报的机器名会照原样显示（界面不核对它，也无法核对）
```

装置是一个**真 socket** 上的 `http.createServer`，回一份全假的、全绿的 `/api/status`。

`6.1` 是这些证据里最该被记住的一行：谎报的门禁**通过了**。
这不是缺陷，是这一层的**职责边界** —— 界面把坏消息显示成好消息的前提，
是有人能给它一份坏掉的输入；而它自己既没有义务、也没有能力去核验那份输入。

`6.3` 是这条边界之外的一点余量：即便门禁全绿，**平台可调用**仍然打不开，
因为它要的是一条**正面**的隧道读数，而谎报者只报了门禁。
这提醒的是判据设计：把结论建在「必须有正面证据」上，比建在「没有反面证据」上更难被一份假数据带偏。

`6.4` 与 `6.3` 相反地说明：机器名会被**照原样**显示。这一格没有防线，
也不该有 —— 界面核对不了「这台机器是不是这台机器」。

### 6.1 帮助：按处境挑选，没有处境时一条都不给

```
PASS 6.5 没有会话时给三条（启动服务 → 打开控制台 → 那个 404）
PASS 6.6 一切正常时**一条都不给**（常驻的帮助文本会被读过一次然后被忽略）
PASS 6.7 全部帮助七条，且都带一句「什么时候用」
```

`6.6` 是这一组里唯一一条「什么都不显示」的断言，也是最容易做错的一条：
一份永远列着七条的帮助，与一份按处境挑出三条的帮助，在截图里看起来差不多，
而在操作者那里是「照着做」与「直接忽略」的区别。
