## 1. 验收标准逐条

### 验收标准 1（前半）· 大量文件时输出有界

```
PASS 1050 条的目录：一次调用只返回一页，且只向护栏问一次 — 返回 200 条 / 目录询问 1 次 / 询问路径=["big"]
PASS 页满时给出可续读的游标，并明确标为不完整 — truncated=true incomplete=true 理由=已达到单页上限 200 条，本页之后仍有条目；请用 next_cursor 继续。
PASS 整棵树在默认限额下不会被一次调用走完（根这一层的目录询问只有 1 次） — 目录询问 1 次 / 本次返回 8 条 / 已达到深度上限 depth=0，有 5 个目录未进入，其内容未包含在本次结果中。
PASS 页面上限抬到 1200（> 护栏硬上限 1000）时按窗口续取：1050 条一条不少 — 返回 1050 条 / 目录询问 2 次（第一次被护栏夹到 1000）
PASS 条目的 ordinal 顺序连续到末条（窗口之间不重不漏） — 首=f0000.txt 末=f1049.txt 去重后=1050
PASS 同一棵树用两种页大小各翻一遍：序列逐条相同（分页边界不改变顺序与完整性） — 粗页 6 页 / 细页 22 页 / 共 1068 条
PASS 翻页结果无重复条目，且覆盖了 1050 条的大目录与深层条目 — 唯一路径 1068 条 / 含 small/nested/deep.txt=true
```

**「有界」的判据是"问了护栏几次"，不是"返回了几条"。** 一个 1050 条的目录，
如果实现是"列全再截断"，返回的条数看起来一样（200），但代价是 1050 条的
内存与一次全量扫描。因此第一行断言的是 `calls.list === 1`：**攒满一页就停**。
护栏那边也有一层同样的设计（`$SCRIPT:LIST_HARD_CAP`，常驻内存只有 `max+1` 条
记录），两层各有各的理由：护栏管的是"一次调用能占多少内存"，本层管的是
"一次遍历能占多少时间/多少次系统调用"。

**页面上限大于护栏硬上限时不会静默少列。** `MAX_DIRECTORY_ENTRIES` 是 200，
但操作者可以把它调大（LWB-018 的限额覆盖）；一旦调到 1200，单次目录询问
仍然只能拿到护栏的 1000 条上限。第四行证明剩下的 50 条是靠 `after_name`
续窗取回的（目录询问 2 次），而不是被丢掉 —— 这类"配置组合下的静默少列"
只能靠一条真实的大目录用例发现。

**两条独立的翻页路径互相印证。** 第六行用 200 与 50 两种页大小各翻一遍整棵树
（1068 条：1050 + 其它），要求序列**逐条相同**。这比"和一次列完比"更强：
一次列完在 1050 条的目录上根本做不到（页面上限就是 200），
而两次不同粒度的分页必须落到同一个序列上，才说明分页边界没有改变顺序。

### 验收标准 1（后半）· 目录变化可以返回游标失效或明确不完整状态

```
PASS 深度上限：明确标为不完整，并说出有几个目录没进入（数字与结果自洽） — 已达到深度上限 depth=0，有 5 个目录未进入，其内容未包含在本次结果中。（可由结果算出的可进入目录数=5）
PASS 目录询问预算用尽：提前结束、标为不完整、并给出可续读的锚点 — 询问 1 次 / 本次调用的目录询问次数已达到上限 1，遍历提前结束；请用 next_cursor 继续。
PASS 用该锚点续读：拼接结果与一次列完逐条相同（不重不漏） — 拼接 4 条 = 一次列完 4 条
PASS 子树在遍历途中消失：跳过它、把路径与护栏码写进不完整原因、其余条目照常返回 — 子目录 van/gone 未能枚举（护栏码 NOT_FOUND），该子树未包含在本次结果中。；仍返回 ["van/gone","van/ok.txt"]
PASS 锚点在续读前被删除：从它的位置继续（既不重来，也不跳过后续条目） — 第一页=["x1.txt","x2.txt"] 删掉锚点 x2.txt 后续读=["x3.txt"]
PASS 游标声称的起点对象与磁盘上的身份不符时被拒绝（身份取自真实 NTFS，不是字符串） — small=00b100000000d980 mid=00730000000e5f58 ⇒ READ_TOKEN_STALE/CURSOR_BASE_CHANGED
PASS 游标与请求的深度不符时拒绝，而不是取较小值继续 — READ_TOKEN_STALE/CURSOR_DEPTH_MISMATCH
PASS 游标被用到另一个目录上时拒绝（起点路径不同） — READ_TOKEN_STALE/CURSOR_BASE_MISMATCH
PASS 伪造的游标被拒绝（签名，不是可读的坐标） — READ_TOKEN_STALE/TICKET_MALFORMED
NOTE 同名目录删除后重建的物理身份 — before=0022000000119137 after=0023000000119137（不同 ⇒ 身份判定在此形态下无区分力：判定有区分力）
PASS 起点目录被同名新目录替换后，游标失效（真实 file_id 变化） — READ_TOKEN_STALE/CURSOR_BASE_CHANGED
```

**"不完整"必须是一个可以说清楚的词，而不是沉默。** 三行 `incomplete_reason`
分别覆盖三种"没看完"的原因：深度上限（并给出未进入的目录数）、
目录询问预算用尽、子树枚举失败（并给出路径与**护栏码**）。第一行的数字
由结果本身算出（`目录 && !excluded` 的条目数），不是抄进断言的常量 ——
抄来的数字在夹具变化后仍会"通过"，而它已经不再描述事实。

**错误文本里只带路径与护栏码，不带护栏的自由文本。** 护栏的错误消息里可能
包含我们没打算回给模型的东西（例如它内部尝试过的完整路径）。因此
`skipped` 只记 `{path, code}`，理由串也是我们自己拼的。

**"起点被换掉"在真实 NTFS 上是可构造的**：删除目录再在同名处建一个新的，
文件索引确实变了（`NOTE` 行给出了两个不同的值）。这条用例第一版是 **FAIL** ——
原因见 §4.1。

### 验收标准 2 · 不能枚举未授权文件根的兄弟文件

```
PASS 真实 junction 指向工作区之外的目录：条目返回但不进入、不带长度、目标内容一条都不出现 — excluded=true size=null 是否进入=false 含 outside-only=false
PASS 结果里的每一条路径都能被护栏按同一拼写重新解析（逐条回验，越界会被护栏拒绝） — 回验 7/7 条；被拒=[]
PASS 条目路径不含穿越段，也不是绝对路径 — 样本=["small/a.txt","small/b.txt","small/nested"]
PASS 穿越路径在探针阶段被拒绝，且一次目录询问都不发生 — PATH_UNSAFE / 目录询问 0 次（护栏码 PATH_UNSAFE）
```

**重解析点是这条验收标准在真实磁盘上唯一的形态。** 沙箱里有一个真实的
junction（`mklink /J`，**不需要管理员权限**）指向工作区根之外的目录。
遍历对它只做一件事：把条目本身返回并标 `excluded`。
不进入、不 stat（`size` 保持 `null`）—— 因为 `Length` 会跟随链接去问
目标对象的长度，那本身就是一次跨边界的读取。

**"逐条回验"是这条标准的正面证据。** 前三行说的是"没有出现不该出现的东西"，
第四行反过来问："出现了的是不是都真的在根之下"。把结果里的每一条路径
拿回护栏重新解析，要求它被接受**且**返回同一个规范拼写 —— 护栏自己会拒绝
越界路径，因此这一步等于让护栏替我们复核了每一条。7/7 通过。

### 验收标准 3 · 隐藏/拒绝对象不在列表和错误中泄露详细信息

```
PASS 真实 .env / .ssh（含私钥）/ 令牌名文件：名字与内容都不出现在结果里 — denied_entries=3 泄露片段=[]
PASS 被拒绝的目录从未被枚举（一次目录询问都没有落到它们身上） — 询问过的路径=[""]
PASS 被拒绝的条目计进 scanned_entries，但仍不进 entries（数过什么就对得上什么） — scanned=13 entries=10 denied=3
PASS 遍历只进入允许的目录：被拒绝的 (.env/.ssh) 与被排除的 (node_modules/junction) 都不进入 — 询问过的路径=["","anchor","big"]
PASS 搜索排除目录：返回并带 excluded 标记、不进入；但显式列举它仍然拿得到内容（「不扫」不是「不许读」） — 标记=true 显式列举=["node_modules/pkg"]
PASS 起点是一个真实的 .env 目录：整次列举被拒，且一次目录询问都不发生 — POLICY_DENIED/HD-ENV / 目录询问 0 次
PASS 工作区根自己就是 .lwb 目录时，整次列举被拒（根的判决路径不是空串，否则这条会通过） — POLICY_DENIED/HD-PLUGIN-STATE / 目录询问 0 次
PASS 起点不是目录时拒绝并指路 file_read（护栏的 expect 不执行这条判断，因此这一判必须在调用方） — INVALID_ARGUMENT/NOT_A_DIRECTORY / 目录询问 0 次
PASS 单文件工作区：回执路径是空串、条目一条、且明确是完整的 — path="" 条目=[{"p":"","n":"plain.txt","s":6}] incomplete=false
```

**判据是 `JSON.stringify(结果)` 里不含那些名字。** 只断言"不在 `entries` 里"
是不够的：泄露可以从 `incomplete_reason`、错误消息、乃至游标的载荷里发生。
因此第一行对整个结果对象做全文检查，样本包括 `.env`、`.ssh`、`id_rsa`、
`ghp_`、`PRIVATE KEY` 五个片段。

**"没进列表"与"没被枚举"是两件事，都要证。** 第二行断言目录询问**从未**
落到 `.ssh` / `.env` 上 —— 一个先枚举再过滤的实现会返回同样的列表，
但它已经把那些目录的内容读进了进程内存，而且它的错误路径会泄露这些名字。

**`.env` 的两种形态都被覆盖**：作为根下的条目（被丢弃）、作为一个**目录**
被显式列举（整次拒绝）。第七行是其中最容易被漏掉的一种 —— 把工作区根
登记在一个真实的 `.lwb` 目录上。这一条之所以有价值：判决路径**空串不命中
任何按名字匹配的规则**，所以只有"根的名字确实来自注册的绝对路径"时它才会被拒。
它一旦通过，就说明根的判决路径不是空串。

## 2. 实测：三处只有真实文件系统才暴露的行为

### 2.1 一次列举不可能覆盖整棵树（页面上限 200 vs 1050 条的目录）

`LIMITS.MAX_DIRECTORY_ENTRIES = 200`。沙箱里有一个 1050 个文件的目录，
因此**任何** `depth` 足够深的调用都不可能一次列完这棵树。
本文件的多个用例第一版都栽在这上面（见 §4.2）：它们在根这一层断言
"被拒绝的条目都在结果里"，而遍历其实在 `big/` 里填满页面就停了 ——
`ghp_*` 排在 `big` 之后，压根没被处理到。这不是实现的缺陷，
而是**分页本身就是被测行为**：一次调用看不完整棵树是设计之内的事。

### 2.2 排序决定了谁会先被处理完

条目按 **ordinal（UTF-16 码元序）** 遍历，与护栏的 `CompareOrdinal`
和 TypeScript 的 `<` 是同一套顺序。`.env`(0x2E) < `.ssh` < `big`(0x62) <
`ghp_` < `junction` < ... 这个顺序解释了为什么"在根这一层做的断言"和
"在子树里做的断言"会有不同结果，也是 §2.1 那批用例失败的直接原因。

### 2.3 桩与真实护栏在"根"上的分歧（见 §5.1）

桩允许 `resolvePath('')` 返回根目录的信息，真实护栏**故意拒绝**它并给出
指路（"列举根目录请用 listDirectory"）。单元测试因此看不见这个分歧，
是 `tests/windows/files-list.test.ts` 首次运行时报出来的（第 4 项起连续失败）。

## 3. 实测：护栏硬上限之下的窗口续取

```
PASS 页面上限抬到 1200（> 护栏硬上限 1000）时按窗口续取：1050 条一条不少 — 返回 1050 条 / 目录询问 2 次（第一次被护栏夹到 1000）
```

护栏自己夹取 `max_entries`（`LIST_HARD_CAP = 1000`），而且**不会**告诉调用方
"我要的比你能给的多"。因此本层必须处理 `has_more`：页没满 + `has_more`
⇒ 用 `after_name` 续问同一个目录。这条路径在默认配置下永远不会走到
（默认 200 < 1000），只有把限额调大时才出现 —— 属于"配置组合"类缺陷，
靠单元测试的桩（它镜像了 1000 这个上限）与这条真实用例各钉一次。

## 4. 采集过程中发现并修复的真实缺陷

### 4.1 证据脚本自己造了一个"看起来通过"的用例

"起点目录被同名新目录替换后游标失效"这条，第一版是 **FAIL**，
但 FAIL 的原因不在实现里：夹具目录里只放了一个文件，`max_entries: 1` 时
页面刚好装下、没有见证条目，于是**根本没有发出游标**，
续读那次调用实际上是一次全新的列举（返回空目录），它当然不会报错。

修法是把夹具改成两个文件（页面装不下，必然给出游标），并**在用例内断言
装置前提**（`next_cursor === null` 时直接判 FAIL 并说明前提不成立）。
教训与 LWB-013 §4.1 同：**一个用例"没有报错"和"验到了它声称在验的东西"
是两件事**，前提本身也要断言。

### 4.2 遍历在真实护栏上失败：护栏拒绝"解析目录工作区的根"

`tests/windows/files-list.test.ts` 首次运行 21 项中 9 项失败，全部是同一个
根因：

```
相对路径为空，而工作区根是一个目录：C:\Users\…\lwb-files-list-…
本操作需要一个具体目标；列举根目录请用 listDirectory。（护栏码 PATH_UNSAFE）
```

读取侧从来没有遇到它，因为**读一个目录根本不是合法操作**（`gatePathFor`
对"目录工作区 + 空路径"是显式拒绝的）。但列举根是最主要的一次调用。

修法不是在护栏上开洞，而是承认护栏说得对：`resolvePath` 回答的是
"这个路径是哪一个对象"，而"不用路径、直接说整个根"根本不是一次寻址。
因此本层新增 `resolveBase()`：**除这一种情形外一律走探针**；
根这一种直接取作用域里的事实（`canonical: ''`、身份取 `root_volume_id`/
`root_file_id`、`is_directory: true`）。这不是省掉一次证明，而是省掉一次
**重复**的证明 —— 护栏的 `Open-GuardedChain` 在**每一次**调用里都会拿句柄
算出的卷序列号与文件索引去比对请求里声明的根身份，不符即
`ROOT_IDENTITY_MISMATCH`。因此写进游标的 `base_file_id` 仍是每次都被重新
核实过的那个值，而不是一个被抄下来的字符串。

同一次运行还改掉了另一个更隐蔽的问题：`singleFileListing()` 之前拿到的是
**判决路径**（单文件工作区里被换成了根的文件名）当回执路径，
于是单文件工作区的 `path` 会回成文件名而不是空串 —— 与 `file_read`
在该工作区里的约定不一致。现在回执路径与判决路径是两个值，各取所需。

## 5. 偏离项与设计取舍

### 5.1 判决路径与回执路径是两个不同的值

`gatePathFor`（读取用）在"目录工作区 + 空路径"上**拒绝**；`baseGatePathFor`
（列举用）在同一个输入上返回**根的名字**。两者只差一个分支，但问的不是
同一个问题：

- 读取问"我要读的这个**文件**叫什么名字"——根在目录工作区里不是文件；
- 列举问"我要枚举的这个**基准**叫什么名字"——根永远有一个名字。

共用一份 `requireCanonicalPath` + `rootNameOf`，而不是给一个函数加
布尔开关：**安全相关的函数上加开关，等于给调用方一次选错的机会**，
而两条路径本来就该各自说清自己在问什么。

### 5.2 游标锚点是"路径 + 运行时探测"，不是序号偏移

深度优先**先序**的遍历里，"锚点之后"取决于锚点现在是什么：
是文件 ⇒ 它的兄弟；是目录且本次会进入 ⇒ **它内部的第一条**。
按序号偏移（"第 200 条之后")会在目录增删时整页漂移。因此游标承载
`anchor_path`，续读时用一次 `resolvePath` 探测它现在是不是目录。

锚点**消失**（`NOT_FOUND`）不是错误：它（以及它内部的一切）已经没了，
"从它的兄弟继续"正是这棵树现在该有的顺序；其它任何失败**拒绝整个游标**，
因为"猜一个位置继续"会产出条目缺失或重复的结果 —— 那种结果看起来是完整的。

### 5.3 `depth` 不随游标静默漂移

游标里带着 `depth`。续读时省略 `depth` 就用游标里的那个；显式给出且与
游标不符则**拒绝**（`CURSOR_DEPTH_MISMATCH`）。取较小值"继续"看起来更保守，
实际是让调用方拿到一份自己没要求过、也没有被告知的遍历结果 ——
同 LWB-013 偏离项 27（游标不承载页大小）是同一条理由的两面。

### 5.4 遍历时不 stat 重解析点，也不进入它

`excluded` 有两种来源：命中搜索排除规则、以及**是重解析点**。
两者的共同处置是"返回但不进入"，但重解析点额外要求**不取长度** ——
`Length` 会跟随链接去问目标对象的长度，那是跨边界的信息泄漏。
条目仍然返回，因为"这里有一个链接"本身是真实且有用的信息；
把它藏起来会让目录看起来少了一项。

### 5.5 `incomplete` 与 `truncated` 是两个不同的词

- `truncated` = 发出了游标（还有下一页）；
- `incomplete` = 这次的视野**有洞**（深度不够、预算用尽、子树没枚举成功），
  并且 `incomplete_reason` 会说出是哪一个。

两者可以同时为真，也可以各自为真：深度限制下没有游标但有洞；
页满时有游标（洞只是"还没看到"）。把两者合并成一个词，
调用方就无法区分"接着要下一页"和"这次的结果不能用"。

### 5.6 「不扫」不是「不许读」

搜索排除目录（`node_modules` 等）会返回条目并带 `excluded: true`，
但遍历不进入。**显式**列举它仍然拿得到内容（实测通过）。
把 `excluded` 当成安全边界是错的：它只影响自动遍历，
真正的边界是硬拒绝规则与闸门。
