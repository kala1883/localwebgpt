# 架构决策记录（ADR）

本目录记录**已经决定**且会影响后续实现的事项。每一份 ADR 回答三件事：
决定了什么、为什么、以及在什么条件下应当推翻它。

> ADR **不是**设计说明。设计方案在 `docs/LWB_COMPLETE_PLAN.md`（冻结基线）。
> ADR 记录的是设计落到本机现实之后产生的偏离与选择。

## 本仓库 ADR 的写法约定

1. **区分「已验证」与「未验证」。** 已锁定但没跑过的依赖写「已锁定」，
   不写「可用」。未执行项单独成节，不混进结论里。
2. **把限制写在显眼处。** 例如 ADR-001 §6 直接写明验收负责人未指定，
   ADR-003 §6 列全证据缺口。一份读起来处处通过的文档，价值低于一份列出缺口的小文档。
3. **状态为「BLOCKED」的任务不写成通过。** 目前 LWB-002（真实 ChatGPT 账号与隧道）
   因缺少凭据处于 BLOCKED，其全部结论在 ADR-003 与 `compatibility.md` 中标为未验证。
4. **推翻条件要写出来。** 见下方。

## 推翻条件

| ADR | 在什么条件下应当重新决定 |
| --- | --- |
| 001 | 操作者不接受 §3 的排除项，或验收负责人指定后要求调整范围 |
| 002 | 原生工具链可用（Rust/MSVC/Windows SDK），或需要针对 FAT32/ReFS 支持 |
| 003 | 真实隧道验证后发现协议修订与 SDK 1.30.1 不兼容，或账号接入方式发生变化 |
| 005 | 引入真正按 workspace 限制的 OS sandbox，或 command_exec 的实际权限超过操作者可接受范围 |
